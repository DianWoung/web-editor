# 场景运营中台 SaaS 化重设计

## 背景

当前系统已经具备：

- 场景管理：`/scenes`
- 场景编排：`/editor?sceneId=...`
- 场景预览：`/scenes/:sceneId/preview`
- 场景总览：`/scenes/:sceneId/overview`
- 设备详情：`/detail/:deviceId`
- 资产管理：`/assets`

但从产品体验上看，当前界面仍有 4 个主要问题：

1. 顶层入口仍偏“页面导航”，不是“围绕场景对象的工作台”。
2. `/scenes` 已经承担主入口职责，但视觉和信息层级还不够像真正的运营中台。
3. 编辑、预览、总览三个页面仍然各自成型，缺少统一的产品语法。
4. 资产管理和场景管理仍然在争夺一级导航心智，不利于后续接入实时设备数据。

本轮目标不是单纯换皮，而是把当前系统重构为一套更接近现代 SaaS 产品的“场景运营中台”。

## 目标

本轮设计需要达成：

1. 明确产品主心智为“场景运营中台”，而不是传统工业后台或展示型驾驶舱。
2. 以 `/scenes` 作为唯一顶层主入口，把场景作为一级业务对象。
3. 使用“浅色信息层 + 深色实时态视图区”的双层视觉结构，兼容后续设备实时数据接入。
4. 让编辑页、预览页、总览页成为同一工作台下的三种子工作区，而不是三个独立产品。
5. 将资产管理从一级导航降级为场景工作区中的次级入口。
6. 为未来接入实时设备状态、告警、KPI 和设备详情跳转预留稳定的信息架构。

## 非目标

本轮不包含：

- 重写现有运行态 API 合同
- 重写设备详情页的数据模型
- 重做 3D 渲染底层或 Three.js 壳层
- 新增复杂权限系统或多角色工作台
- 引入全新可视化图表体系

## 产品定位

### 产品角色

新版产品定位为：

**场景运营中台**

用户首先管理的是“场景”，而不是“页面”、不是“设备清单”、也不是“大屏视图”。  
场景是所有后续行为的上下文来源：

- 编辑场景
- 预览场景
- 查看运行态总览
- 查看设备详情
- 进入资产配置入口

### 与其他方向的区分

#### 不是传统企业中台

传统企业中台会把功能拆成多个并列模块导航，例如：

- 场景管理
- 资产管理
- 运行监控
- 系统设置

这种方式实现简单，但会削弱“场景”作为业务主对象的连续性。

#### 不是展示型孪生驾驶舱

大屏或驾驶舱以视觉冲击和运行展示为核心，不适合作为日常管理入口。  
本系统后续需要接入实时设备数据，但主入口仍应服务“运营与编排”，而不是“展示”。

## 总体设计方向

### 视觉方向

采用：

**浅色信息层 + 深色实时态视图区**

原因：

1. 浅色层更适合承载场景列表、表单、管理动作、状态说明等高频信息。
2. 深色层更适合承载 3D 画布、运行态视图、实时告警、设备状态和数据更新反馈。
3. 这种分层可以在不重做整体产品视觉的情况下，平滑接入后续实时设备数据。

### 风格关键词

- 现代 SaaS
- 信息层级清晰
- 轻运营工作台
- 深色实时态舞台
- 克制但精致
- 不使用传统工业软件式重边框和大面积深色面板堆叠

## 信息架构

## 顶层导航

顶层导航收敛为以场景为核心的主结构：

- `场景`

其余能力按层级处理：

- `运行态`
  - 不作为一级入口存在
  - 作为场景的子视图，通过 `/scenes/:sceneId/overview` 打开
- `资产管理`
  - 从一级导航下沉为场景工作区中的次级入口
- `设备详情`
  - 由场景总览页或运行态视图内的设备点击进入

### 导航原则

用户进入系统后，不应先做“模块选择”，而应直接进入场景工作台。  
因此：

- `/` 重定向到 `/scenes`
- 顶栏主品牌保留
- 主导航只强调 `场景`
- 资产入口作为工作区内按钮、次级入口或场景级操作出现

## 首页：`/scenes`

`/scenes` 从“场景列表页”升级为：

**场景运营工作台**

### 页面结构

采用左右双栏主结构：

- 左侧：场景列表
- 右侧：当前选中场景的运行摘要与快捷入口

### 左侧：场景列表区

左侧承担：

- 新增场景
- 浏览场景
- 选择当前场景
- 删除场景

每个场景卡片只保留必要信息：

- 场景名称
- 场景备注摘要
- 最近更新时间
- 设备数
- 管线数
- 当前状态标记（如当前工作场景）

每个场景条目动作：

- `总览`
- `预览`
- `编辑`
- `删除`

### 右侧：当前场景运行摘要区

右侧不是“重复的场景卡片”，而是：

**当前场景的实时态概览面板**

页面要为未来实时数据预留两层内容：

#### 第一层：状态摘要

- 在线设备数
- 活动告警数
- 最近更新时间
- 异常设备摘要

#### 第二层：业务指标

- 总功率
- 负载
- COP / 效率类 KPI
- 其他业务指标占位

#### 第三层：深色实时态主视区

深色区域承载：

- 实时态 3D 主视图
- 告警流
- AI 建议摘要
- 设备点击跳转入口

右侧区域在当前阶段即使只有占位数据，也要按未来实时数据产品来设计，不再仅做静态场景说明。

### 新增场景交互

顶部不再常驻创建表单，只保留一个：

- `新增场景`

点击后弹出对话框，填写：

- 场景名称
- 场景备注

确认后：

1. 创建场景
2. 刷新工作台列表
3. 直接进入编辑页

## 子工作区体系

编辑、预览、总览不再各自使用独立产品语法，而是统一为：

**场景工作台的三种工作模式**

三页共享：

- 同样的场景上下文
- 同样的页面顶层结构
- 同样的浅色信息层 + 深色主视区规则
- 一致的返回路径

### 1. 编辑页

编辑页职责：

- 场景编排
- 对象属性编辑
- 场景名称与备注维护

#### 保留

- 场景名称
- 场景备注
- 保存
- 撤销
- 返回场景工作台
- 左侧设备库
- 中间 3D 编排画布
- 右侧属性面板

#### 移除或降级

- JSON/调试工具作为主流程区域
- 重复说明性卡片
- 与实时态无关的多余表单

#### 页面原则

编辑页是操作密度最高的页面，但必须聚焦“编排”本身。  
场景级元信息收敛到顶部一条上下文栏，不再挤占主体。

### 2. 预览页

预览页职责：

- 查看场景效果
- 操作视角
- 开关流动状态
- 快速判断当前场景是否正确

#### 保留

- 返回场景工作台
- 进入编辑
- 流动状态开关
- 只读 3D 视图
- 少量摘要信息

#### 摘要只保留

- 场景名称
- 场景备注
- 更新时间
- 设备数
- 管线数

#### 不承载

- 删除
- 编辑表单
- 长列表说明区
- 运行态 KPI

预览页是“效果确认页”，不是第二个管理页。

### 3. 总览页

总览页职责：

- 承接场景运行态
- 展示当前场景的实时数据摘要
- 提供设备详情跳转

#### 页面结构

- 顶部：场景上下文栏
- 左/上摘要区：状态 + KPI
- 深色主视区：运行态 / 3D 视图
- 辅助区：告警、建议、设备跳转

#### 未来扩展原则

总览页是未来接入实时设备数据的主要页面，因此本轮设计必须保证：

- 深色主视区可持续扩容
- 状态卡和 KPI 卡具有模块化插拔能力
- 设备点击链路可以稳定指向 `/detail/:deviceId`

## 资产管理入口重组

资产管理不再作为一级导航长期常驻。

### 新位置

资产管理入口应下沉为：

- 场景工作台中的次级入口
- 或场景上下文下的“配置入口”

### 原则

资产能力仍然重要，但它是配置和供给能力，不是用户每天最先进入的一级业务对象。  
对于这套系统而言，主心智应始终是“管理和运营场景”，而不是“先进入资产模块”。

## 视觉系统原则

### 1. 明暗分层

- 浅色：信息、列表、表单、状态说明
- 深色：3D、实时态、运行数据主视区

### 2. 卡片语法

卡片不再只是简单边框盒子，而应区分：

- 运营信息卡
- 状态指标卡
- 深色视图区容器
- 危险操作对话框

### 3. 字体与层级

视觉上采用更接近现代 SaaS 的排版：

- 顶层标题更大、更轻、更有留白
- 列表信息更克制
- 实时指标数字更突出
- 说明文案弱化

### 4. 动效原则

只在关键层级使用动效：

- 场景切换时右侧摘要轻量过渡
- 深色实时态区可保留有限动效
- 不为所有按钮和卡片堆叠无意义微交互

## 状态与数据预留

为后续设备实时数据接入，页面设计中需要明确三种数据状态：

1. `无数据`
2. `加载中`
3. `已连接并持续刷新`

这些状态尤其要体现在：

- 场景工作台右侧实时摘要区
- 总览页状态卡
- 深色实时态视图区

这样后续接入真实设备数据时，不需要再次推翻页面结构。

## 实施边界建议

本轮 UI 重设计建议优先改这几块：

1. 顶层导航收敛
2. `/scenes` 首页重做
3. 编辑/预览/总览三页统一上下文结构
4. 资产入口迁移到场景工作区
5. 视觉 token 和基础排版系统重做

不建议第一轮就同步大改：

- 运行态数据源
- 设备详情数据结构
- 资产编辑流程
- 3D 引擎底层实现

## 验收标准

设计完成后，产品层面应达到：

1. 用户进入系统后，能自然理解“场景”是一级操作对象。
2. `/scenes` 看起来像运营工作台，而不是普通列表页。
3. 编辑、预览、总览三页具有一致的产品语法。
4. 资产管理不再抢占一级导航心智。
5. 页面布局明显为未来实时数据接入做了准备，而不是静态页面拼接。
