# 场景独立预览页设计

## 背景

当前仓库已经有：

- 场景管理页 `/scenes`
- 场景编排页 `/editor`
- 总览页 `/overview`

场景管理页目前只能做文本级预览，无法直接查看“已配置设备组合”的三维效果。用户需要一个独立、只读、不可编辑的预览页，用于查看场景布局效果、操作视角，并切换管线流动状态。

## 目标

新增一个独立路由的场景预览页，用于只读查看命名场景：

- 从场景管理页打开
- 可查看三维设备组合效果
- 可操作视角
- 可切换管线流动状态
- 不可编辑、不保存、不修改场景

## 非目标

本次不包含：

- 在预览页编辑设备或管线
- 在预览页保存场景
- 运行态 KPI、告警、点位趋势等运维信息
- 预览页内切换到其他场景
- 新增新的场景数据模型

## 用户流程

### 场景管理页

在 `/scenes` 的每个场景条目上提供两个入口：

- `预览`
- `进入编辑`

点击 `预览` 后跳转到：

- `/scenes/:sceneId/preview`

### 预览页

预览页加载指定命名场景并展示：

- 三维只读画布
- 设备数量、管线数量、端口组数量
- 流动状态开关
- 返回场景管理
- 进入编辑

## 路由设计

新增路由：

- `/scenes/:sceneId/preview`

保留现有：

- `/scenes`
- `/editor?sceneId=...`

## 组件设计

### 1. `ScenePreviewPage`

职责：

- 读取 `sceneId`
- 拉取命名场景
- 拉取设备目录
- 维护只读预览页的局部 UI 状态
- 组织页面布局

状态：

- `scene`
- `catalog`
- `loading`
- `error`
- `flowEnabled`

### 2. `ScenePreviewCanvas`

职责：

- 接收 `scene`、`catalog`、`flowEnabled`
- 渲染只读三维视图
- 支持 orbit controls
- 不暴露编辑行为

设计原则：

- 不依赖 `sceneStore`
- 不写入任何全局编辑态
- 尽量复用现有 `DeviceInstance`、`PipeRun`、`RoomFloor`

### 3. `ScenePreviewSummary`

职责：

- 展示场景名称
- 更新时间
- 设备/管线/端口组统计
- 提供 `返回场景管理` / `进入编辑`
- 提供流动状态开关

## 复用策略

### 推荐边界

预览页不复用 `OverviewPage`，也不直接依赖全局 `sceneStore`。

原因：

- `OverviewPage` 带有运行态轮询与 KPI 语义，不适合纯场景预览
- `sceneStore` 是编排态全局状态，预览页写入它会造成页面之间相互污染

### 可复用部分

直接复用已有展示组件：

- `DeviceInstance`
- `PipeRun`
- `RoomFloor`
- `loadEquipmentCatalog`

通过新建只读画布壳层把这些组件拼起来，而不是让预览页接入编排状态树。

## 页面结构

预览页采用两栏布局：

- 左侧信息栏
  - 场景名称
  - 更新时间
  - 设备数 / 管线数 / 端口组数
  - 流动状态开关
  - 返回场景管理
  - 进入编辑
- 右侧三维画布
  - 只读查看
  - 轨道控制
  - 点击设备不跳详情

## 交互限制

预览页明确禁止：

- 设备选择后编辑属性
- 删除设备
- 删除管线
- 连线
- 地面放置
- 导入 JSON
- 保存到后端

预览页允许：

- 拖拽视角
- 缩放
- 平移
- 开关流动效果

## 数据流

### 场景管理页

- `GET /api/scene/library`
- `GET /api/scene/library/:sceneId`

### 独立预览页

- 根据 `sceneId` 调 `GET /api/scene/library/:sceneId`
- 调 `loadEquipmentCatalog()`
- 将场景数据和 catalog 直接传给只读画布

不通过：

- `loadCurrentSceneIntoStore()`
- `loadNamedSceneIntoStore()`

因为这两条链路会写入全局场景状态，更适合进入编辑页而不是只读预览。

## 错误处理

预览页需要处理：

- `sceneId` 不存在
- 命名场景读取失败
- 设备目录读取失败

页面表现：

- 展示错误卡片
- 保留返回场景管理入口
- 不渲染空白三维画布误导用户

## 测试策略

至少补以下测试：

### 页面测试

- `/scenes` 列表项包含 `预览`
- 点击 `预览` 跳到 `/scenes/:sceneId/preview`
- 预览页渲染场景名称、统计信息、进入编辑入口

### 预览页集成测试

- 读取命名场景数据并渲染只读页面
- 流动开关能改变本页状态
- 预览页不触发编辑态 store 加载

## 实施步骤

1. 在场景管理页列表增加 `预览` 按钮
2. 新增 `ScenePreviewPage`
3. 新增只读三维画布组件，脱离 `sceneStore`
4. 接入新路由 `/scenes/:sceneId/preview`
5. 补页面测试与集成测试
6. 浏览器验证 `场景管理 -> 预览 -> 进入编辑`

## 风险

### 风险 1：直接复用 `ViewerCanvas` 会被 `sceneStore` 绑定

处理：

- 新建只读预览壳层，不直接复用基于全局 store 的容器

### 风险 2：设备点击行为继承到详情跳转

处理：

- 预览页禁用 `onOpenDevice`

### 风险 3：预览页和编辑页出现展示不一致

处理：

- 共享设备 catalog 和底层渲染组件
- 只让容器层分离，不复制设备渲染逻辑

## 结论

采用独立页面方案：

- 路由：`/scenes/:sceneId/preview`
- 数据源：命名场景 API + catalog API
- 展示方式：只读三维预览壳层
- 场景管理页提供 `预览` 与 `进入编辑` 双入口

这是当前最符合“不可编辑，但可查看效果、操作视角、开启流动状态”的实现方式，同时不会把预览页重新耦合回编排全局状态。
