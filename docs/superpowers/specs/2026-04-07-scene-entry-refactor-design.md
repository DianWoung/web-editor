# 场景入口统一与编排页精简设计

## 背景

当前前端已经有 4 条主要路由：

- `/scenes`：命名场景管理
- `/scenes/:sceneId/preview`：只读场景预览
- `/overview`：运行态总览
- `/editor`：场景编排

现状问题有 4 个：

1. 一级入口分散。用户可以直接从顶栏进入总览和编排，命名场景管理没有成为真正的主入口。
2. 总览没有按命名场景打开，而是默认读取“当前工作场景”，不利于后续接真实设备实时信息。
3. 编排页界面偏重。头部、底部工具条和左右栏位信息较多，主流程不够聚焦。
4. 编排页没有撤销能力，一旦误操作只能手工修复或重载场景。

用户希望把“场景管理”收敛成唯一入口页，然后从场景列表中分别进入：

- 运行态总览
- 场景编排
- 场景预览

同时要求精简编排页，把保存动作移到右上角，并新增撤销功能。

## 目标

本轮改造需要达成：

1. 顶层导航只保留“场景管理”。
2. `/` 重定向到 `/scenes`，`/overview` 不再作为一级入口。
3. 场景列表为每个命名场景提供：
   - `总览`
   - `预览`
   - `编辑`
4. 运行态总览改为按 `sceneId` 打开，并继续保留：
   - runtime 指标
   - 运行态轮询
   - 点击设备进入详情
5. 编排页精简视觉层级：
   - 把“保存”移动到右上角 header 操作区
   - 弱化底部工具条
   - 保留核心编辑能力
6. 编排页增加本地撤销能力，至少覆盖常见场景结构编辑。

## 非目标

本轮不包含：

- 重写后端 scene API
- 引入多人协作或服务器端版本回滚
- 实现重做
- 改写设备详情页运行态合同
- 移除只读预览页 `/scenes/:sceneId/preview`

## 信息架构

### 顶层导航

顶栏从当前的 3 个一级入口收敛为 1 个：

- `场景管理`

页面跳转逻辑调整为：

- `/` → `/scenes`
- `/scenes`：唯一主入口
- `/scenes/:sceneId/overview`：按命名场景打开的运行态总览
- `/scenes/:sceneId/preview`：只读效果预览
- `/editor?sceneId=...`：场景编排

### 场景列表动作

`/scenes` 每个命名场景条目提供 3 个明确动作：

- `总览`：进入该命名场景的运行态总览页
- `预览`：进入只读三维效果页
- `编辑`：进入编排页继续调整

这样“场景”成为跨页面的唯一入口单元，而不是页面先行、场景后选。

## 运行态总览改造

### 新路由

新增总览路由：

- `/scenes/:sceneId/overview`

原 `/overview` 从导航中移除，不再作为正常入口；是否保留兼容跳转由实现阶段决定，优先保留为重定向到 `/scenes`，避免出现脱离场景上下文的总览页面。

### 页面职责

新的场景总览页保留现有能力：

- runtime KPI
- 流动状态开关
- AI 摘要/运行模式展示
- 点击设备进入详情

但数据来源改成“指定命名场景”而不是“当前工作场景”：

- 通过 `sceneId` 读取命名场景
- 将该场景加载到只读展示链路
- 在此基础上继续触发 runtime overview 轮询

### 实现边界

为避免把“进入总览”变成“污染当前编辑中的场景状态”，总览页不应继续无条件使用 `loadCurrentSceneIntoStore()` 作为默认入口。

推荐方式：

- 新增按 `sceneId` 读取命名场景的总览加载链路
- 复用现有 `ViewerCanvas` 或抽更轻的只读壳层
- 继续保留点击设备跳详情行为

## 编排页精简方案

### 布局调整

当前编排页是：

- 顶部标题区
- 左侧设备库
- 中间画布 + 底部 deck
- 右侧属性
- 底部工具条

本轮目标不是重写结构，而是压缩非核心视觉负担，让“画布编辑”更聚焦。建议调整为：

- 顶部：标题 + 来源场景 + 核心操作
- 主体：左设备库 + 中画布/对象面板 + 右属性
- 底部：只保留次级状态、错误、显示开关，不再承担主保存动作

### Header 操作区

右上角保留高频动作：

- `保存`
- `返回场景管理`
- 命名场景来源标识

可选保留：

- `进入总览`

底部工具条移除 `保存到后端` 主按钮，只保留低频动作，例如：

- 导出 JSON
- 导入 JSON
- 加载示例场景
- 清空场景
- 流动开关 / 网格 / 管线显隐 / 吸附 / 重置视角

### 视觉收敛原则

- 减少重复导航动作
- 把保存状态放到 header 附近，不再散落在页面底部
- 让左侧设备库和中间画布成为第一视觉焦点
- 把“内部工具提示”缩短，避免大段说明抢占头部空间

## 撤销设计

### 范围

本轮只做本地单人撤销，不做重做。

撤销至少覆盖：

- 新增设备
- 删除设备
- 复制设备
- 更新设备名称
- 更新设备系统
- 更新设备位姿
- 新增管线
- 删除管线
- 清空场景
- 导入/加载场景

### 不要求覆盖

- 纯 UI 开关，例如显示网格、流动状态、吸附设置
- 短生命周期错误消息
- 摄像机视角

### 状态模型

推荐把撤销历史限制在“场景结构状态”层，而不是整个 store：

- `version`
- `devices`
- `portGroups`
- `pipes`
- `selection`

新增历史栈：

- `historyPast: SceneStateSnapshot[]`
- `historyPresent: SceneStateSnapshot`
- `historyLimit`

或者更贴合当前 store 的方式：

- 在 `sceneStore` 内新增 `undoStack`
- 所有会改动场景结构的 action 在写入前先 push 当前快照
- `undo()` 从栈顶恢复上一个快照

### 触发方式

撤销需要提供两种入口：

- header 按钮：`撤销`
- 键盘快捷键：`Cmd/Ctrl + Z`

按钮状态：

- 没有可撤销历史时 disabled

### 历史去噪

设备拖拽是高频更新点，不能在每一帧 transform 时都写一次历史，否则撤销栈会失控。

因此拖拽相关历史要采用“提交点”策略：

- 拖拽开始时记录原状态
- 拖拽结束时若位置/旋转实际变化，则只入栈一次

如果当前架构短期难以识别拖拽生命周期，则第一版可以退一步：

- 对拖拽更新做最小节流/比较
- 保证只有确实变化时才写历史

但不建议把每次 pointer move 都压入撤销栈。

### 需要新增/扩展的前端单元

   - 只保留 `场景管理`

   - hero 区不再承载一级导航替代逻辑

3. `SceneOverviewPage` 或改造 `OverviewPage`
   - 接收 `sceneId`
   - 按命名场景加载
   - 保留 runtime KPI、设备跳详情、流动开关

4. `EditorPage`
   - header 右侧增加保存/撤销/返回场景管理
   - 压缩说明文字
   - 移除底部工具条中的主保存按钮

5. `SceneJsonToolbar`
   - 降级为次级工具区
   - 删除保存主按钮
   - 暴露可复用的保存状态文案时机，或者把保存逻辑上移

6. `sceneStore`
   - 增加撤销历史与 `undo`
   - 给结构修改 action 统一接入 history

## 数据流

### 场景管理页

- `GET /api/scene/library`
- `GET /api/scene/library/:sceneId`

### 场景总览页

- 根据 `sceneId` 读取命名场景
- 将场景写入只读展示链路
- 继续轮询 runtime overview

### 编排页

- `sceneId` 存在时加载命名场景
- 保存时继续走 `PUT /api/scene/library/:sceneId`
- 无 `sceneId` 时保留当前工作场景保存逻辑

### 撤销

- 完全在前端本地 store 中处理
- 不直接调用后端
- 只有用户点击保存时才持久化当前结果

## 错误处理

### 场景总览页

需要处理：

- `sceneId` 缺失
- 命名场景读取失败
- 设备目录加载失败
- runtime overview 加载失败

页面策略：

- 保留返回场景管理入口
- 将场景错误和 runtime 错误分开呈现

### 编排页

需要处理：

- 保存失败
- 无可撤销项
- 导入非法 JSON

页面策略：

- 保存反馈在 header 就近展示
- 撤销按钮无历史时禁用
- 错误信息仍放在底部状态区或轻量 toast 区

## 测试策略

### 导航与路由

- 顶栏只显示 `场景管理`
- `/` 重定向到 `/scenes`
- 场景列表包含 `总览 / 预览 / 编辑`

### 场景总览

- `/scenes/:sceneId/overview` 会按指定 `sceneId` 读取命名场景
- 页面保留 runtime KPI 与设备跳详情入口

### 编排页

- 带 `sceneId` 进入时 header 显示场景来源
- 右上角保存按钮触发命名场景保存
- 右上角撤销按钮在有历史时可用

### 撤销

- 新增设备后撤销可恢复到之前状态
- 删除设备后撤销可恢复
- 新增管线后撤销可恢复
- 清空场景后撤销可恢复
- 无历史时撤销按钮 disabled

## 风险

### 风险 1：总览继续依赖全局 sceneStore，切页时会污染编辑场景

处理：

- 明确总览按 `sceneId` 加载命名场景
- 避免保留“无场景上下文”的 `/overview` 主入口

### 风险 2：撤销直接包住全部 store，导致 UI 状态一起回滚

处理：

- 只记录场景结构快照，不记录 UI 开关和错误提示

### 风险 3：设备拖拽会让撤销栈膨胀

处理：

- 只在确认变更时记录一次历史
- 第一版为历史栈设置上限，避免内存持续增长

## 验收标准

满足以下条件即可认为本轮完成：

1. 顶栏只剩 `场景管理`
2. `/` 默认进入 `/scenes`
3. 场景列表每项可进入 `总览 / 预览 / 编辑`
4. 总览页按 `sceneId` 打开并保留 runtime/详情跳转
5. 编排页保存按钮位于右上角
6. 编排页有可用撤销按钮和 `Cmd/Ctrl + Z`
7. 核心页面测试、lint、build 通过
