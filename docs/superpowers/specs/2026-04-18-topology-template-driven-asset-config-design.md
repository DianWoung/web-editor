# 基于连接拓扑模板的资产配置设计

## 背景

当前资产管理页虽然已经把连接点从原始 `ports` 提升到了 `connectors`，但用户操作负担仍然很重。

现状问题主要有三类：

1. 资产页同时暴露了资产主信息、连接语义、几何参数三层内容
2. 用户仍然需要逐个连接点填写 `system / role / direction / medium / side / groupKey`
3. 表单模式和 JSON 模式并列存在，但默认编辑路径仍然偏工程化，而不是业务化

从当前实现看，资产页中的连接点区域本质上还是“自由编辑器”：

- 左侧列表允许新增和删除连接点
- 右侧详情允许修改大部分连接点字段
- JSON 模式仍然是同层级入口

这意味着即使数据结构已经进化，用户面对的仍是一个高自由度、低约束的配置界面。对于真实业务用户，这种模式很难稳定产出正确配置。

## 目标

本轮目标是把资产连接配置从“自由编辑连接点”升级为“基于连接拓扑模板生成并轻量覆写”的模式：

1. 资产页不再让用户自由定义连接结构
2. 连接结构由“连接拓扑模板库”统一管理
3. 资产选择模板后，生成一份自己的连接点快照
4. 资产端只允许修改少数字段：`name` 和 `required`
5. 保持现有发布链路和 `/api/equipment/:assetId/ports` 兼容

## 非目标

本轮不包含：

- 三维拖拽式连接点打点
- 模板变更自动联动已配置资产
- 资产页继续支持任意新增/删除连接点
- 资产页保留 JSON 作为主入口
- 场景层 `portGroups` / `pipe.from` / `pipe.to` 格式升级
- 复杂模板规则引擎

## 核心设计结论

### 1. 模板层级

模板主轴采用“连接拓扑模板”，而不是“设备类型模板”。

原因：

- 连接结构本身具有更强复用性
- 同一设备类型可能存在多个连接拓扑变体
- 不同设备也可能共享同一种连接拓扑

因此：

- 设备类型只作为分类、搜索和推荐信息
- 真正决定连接结构的是拓扑模板

### 2. 模板来源

模板采用“可配置模板库”，而不是固定内置模板。

原因：

- 连接拓扑会持续扩展
- 不同业务线需要新增和维护自己的模板
- 如果只做内置模板，后续还是会回到代码驱动配置

这意味着需要一个单独的模板管理入口，而不是只在资产页中做预设按钮。

### 3. 模板与资产的关系

资产应用模板时，采用“复制快照”，不保持强关联。

规则：

- 资产选择模板时，复制一份模板定义生成资产自己的 connectors
- 后续模板变更，不自动影响已配置资产
- 如果资产需要重新套用模板，必须由用户显式触发

原因：

- 已配置资产需要配置稳定性
- 发布后的资产不应因模板调整而被被动改变
- 快照模型更容易与现有资产发布和版本化系统对接

### 4. 资产端可编辑范围

模板决定结构，资产只允许轻量覆写。

资产端允许修改：

- `name`
- `required`

资产端不允许修改：

- 连接点数量
- `connectorKey`
- `system`
- `role`
- `medium`
- `direction`
- 其它模板定义字段

原因：

- 一旦允许修改过多字段，模板驱动会退化回自由表单
- 连接拓扑必须保持结构性约束
- 资产端只应承担命名适配和必需性标记这种轻量业务调整

## 总体方案

### 方案对比

#### 方案 A：轻模板预填充

- 模板只是生成一组默认 connector 数据
- 套用后继续使用现有自由编辑器

优点：

- 改动最小
- 接入快

问题：

- 模板只是起始值，不是真正的结构来源
- 用户仍然会掉回自由编辑
- 后续很难形成稳定模板库

#### 方案 B：模板库 + 资产快照

- 单独维护连接拓扑模板
- 资产页先选模板，再生成快照
- 资产只允许覆写 `name` 和 `required`

优点：

- 结构边界清晰
- 用户操作负担显著下降
- 与现有 connector 模型兼容
- 适合作为后续模板中心的基础

问题：

- 需要新增模板库模型和页面

#### 方案 C：模板库 + 规则引擎

- 模板支持动态规则、派生、自动补点

优点：

- 长期扩展性强

问题：

- 明显超出当前需求
- 设计和实现成本过高

### 推荐方案

采用方案 B：模板库 + 资产快照。

## 数据模型

### 1. `topology_templates`

连接拓扑模板主表。

建议字段：

- `id`
- `template_key`
- `display_name`
- `category`
- `description`
- `default_system`
- `status`
- `created_at`
- `updated_at`

说明：

- `template_key` 是稳定业务键
- `category` 用于模板筛选和归类
- `default_system` 用于列表展示和推荐
- `status` 支持后续模板上架/停用

### 2. `topology_template_connectors`

模板连接点定义表。

建议字段：

- `id`
- `template_id`
- `connector_key`
- `name`
- `system`
- `role`
- `medium`
- `direction`
- `required`
- `sort_order`

说明：

- 一行定义模板中的一个标准连接点
- 这张表定义连接结构，不包含资产个性化覆写

### 3. `equipment_assets`

资产主表保留现有思路，并新增模板关联信息。

新增建议字段：

- `topology_template_id`
- `topology_snapshot_version` 或等价快照标记

说明：

- `topology_template_id` 表示当前资产来源于哪个模板
- `topology_snapshot_version` 记录资产套用模板时的版本信息，便于后续追溯

### 4. `equipment_connectors`

资产连接点表保留，但语义调整为“模板快照 + 资产覆写结果”。

建议保留字段：

- `id`
- `asset_id`
- `connector_key`
- `name`
- `system`
- `role`
- `medium`
- `direction`
- `required`
- `sort_order`
- `geometry`

建议增加来源标记：

- `template_connector_id`
- `override_name`
- `override_required`

说明：

- `system / role / medium / direction` 来自模板快照
- `name / required` 可以被资产覆写
- `template_connector_id` 用于追溯这条资产 connector 来自哪个模板 connector

### 5. 兼容输出

现有 `ports` 兼容结构继续保留，仍由 connectors 投影生成。

这样可以继续兼容：

- `/api/equipment/:assetId/ports`
- 设备编排页消费逻辑
- 导入包中 `ports.json` 的结构约定

## 页面与交互设计

### 一、资产页改造

资产页从“编辑连接点”改为“选择连接拓扑模板 + 覆写少数字段”。

#### 1. 基础信息区

保留当前资产基础信息和模型上传区，不做大的交互变化：

- 资产标识
- 显示名称
- 类型
- 默认系统
- 渲染风格
- 尺寸
- 模型上传

#### 2. 连接拓扑模板区

新增“连接拓扑模板”区块，展示：

- 当前已选模板
- 模板名称
- 模板分类
- 模板连接点数量
- 模板简介

提供两个动作：

- `选择模板`
- `重新套用模板`

其中：

- 初次配置资产时，通过“选择模板”生成快照
- 已有配置时，通过“重新套用模板”替换当前 connectors，需要明确确认

#### 3. 连接点覆写区

资产页不再显示完整的 connector 详情编辑器，而是显示一个简化表格。

每行展示：

- 模板连接点名称
- 可编辑名称
- `system`
- `role`
- `medium`
- `direction`
- 可编辑 `required`

规则：

- `name` 可编辑
- `required` 可编辑
- 其余字段只读展示

资产页不再提供：

- 新增连接点
- 删除连接点
- 修改结构字段
- JSON 主入口

#### 4. 高级入口调整

JSON 高级模式不再作为资产页连接配置主入口。

建议做法：

- 从资产页主界面移除 JSON 模式切换
- 如确有需要，只保留一个低频“查看快照 JSON”或“导出配置”入口

目标是避免普通用户直接落入底层结构编辑。

### 二、模板库页

需要新增单独的“连接拓扑模板库”页面，职责是维护模板结构。

#### 1. 模板列表

展示：

- 模板名称
- 分类
- 默认系统
- 连接点数量
- 更新时间

支持：

- 搜索
- 分类筛选
- 新建模板

#### 2. 模板预览

展示模板包含的连接点：

- `name`
- `system`
- `role`
- `medium`
- `direction`
- `required`

用于资产页选择模板前预览结构。

#### 3. 模板编辑

模板页承担结构编辑职责，可编辑：

- 新增连接点
- 删除连接点
- `connectorKey`
- `name`
- `system`
- `role`
- `medium`
- `direction`
- `required`
- 排序

JSON 高级模式只保留在模板页。

原因：

- 模板管理员需要结构级编辑能力
- 普通资产配置用户不需要接触这些底层细节

## 接口演进

### 第一阶段

优先在现有资产中心上引入模板驱动，不立即重写全部接口。

建议新增：

- `GET /api/topology-templates`
- `GET /api/topology-templates/:id`
- `POST /api/topology-templates`
- `PUT /api/topology-templates/:id`
- `POST /api/assets/:assetId/apply-topology-template`

其中 `apply-topology-template` 负责：

- 接收模板 id
- 生成资产 connectors 快照
- 返回新的 connectors 列表

### 第二阶段

在资产详情接口中补充模板信息：

- `asset.topologyTemplateId`
- `asset.topologyTemplateName`
- `asset.topologySnapshotVersion`

便于资产页直接展示当前模板来源。

### 兼容接口

以下接口继续保留：

- `PUT /api/assets/:assetId/ports`
- `GET /api/equipment/:assetId/ports`

但使用方式调整：

- `PUT /api/assets/:assetId/ports` 不再作为资产页主入口
- 内部实现继续基于 connectors 生成兼容结构

## 兼容现有导入与发布链路

### 1. 发布链路兼容

资产发布时仍然生成现有兼容输出：

- `asset.json`
- `ports.json`
- `model.glb`

其中：

- `asset.json` 继续来自资产主信息
- `ports.json` 来自“模板快照 + 资产覆写”投影结果

这样可以保证现有设备库和编排页无须同步重构。

### 2. 编排页兼容

场景编排器继续消费当前 `ports` 结构：

- `portGroups[].ports[]`
- `pipe.from / pipe.to = deviceId.portId`

本轮不触碰场景 schema。

### 3. 导入包兼容

现有 importer 约定继续成立：

- 每个资产目录包含 `asset.json`
- `ports.json`
- `model.glb`

只是 `ports.json` 的来源从“人工自由配置”调整为“模板驱动生成”。

## 迁移策略

### 第一阶段：先改资产页

优先目标是降低资产配置难度。

实施内容：

- 资产页接入模板选择
- 资产页只保留 `name` 和 `required` 覆写
- 移除资产页中的连接点自由编辑主路径

价值：

- 最快改善用户体验
- 不需要一次性完成所有后台能力

### 第二阶段：补模板库管理页

在资产页模板驱动稳定后，再补齐模板库 CRUD 能力。

价值：

- 避免一次性做太大
- 先解决使用体验问题，再补齐运营能力

### 第三阶段：整理旧入口

在模板库稳定后，逐步弱化或下线资产页中的旧式自由 connector 编辑入口。

## 风险与权衡

### 1. 模板覆盖不足

如果模板库太少，用户还是会觉得受限。

应对：

- 先提供一批高频拓扑模板
- 模板库页支持快速复制已有模板

### 2. 快照与模板漂移

采用快照后，模板更新不会自动影响资产。

这是有意取舍，不是缺陷。

应对：

- 在资产页显示模板来源
- 提供显式“重新套用模板”动作

### 3. 旧资产兼容

历史资产可能没有模板来源信息。

应对：

- 允许旧资产以“无模板”状态继续存在
- 需要时由人工选择模板重新归档

## 验收标准

满足以下条件视为本轮设计达标：

1. 用户在资产页不需要手工定义连接结构
2. 用户可通过模板选择完成连接结构初始化
3. 资产页只能覆写 `name` 和 `required`
4. 模板页可以维护完整连接结构
5. 已发布资产仍可被现有设备库与编排页消费
6. 现有导入包结构保持兼容

## 推荐实施顺序

1. 为资产详情和 connector 模型补充模板来源字段
2. 新增拓扑模板数据结构和 mock API
3. 资产页接入模板选择与快照应用
4. 将资产页连接区改成“只读结构 + 少量覆写”
5. 新增模板库管理页
6. 保留兼容发布和 `/api/equipment/:assetId/ports` 输出
